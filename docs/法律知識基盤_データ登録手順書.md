# 法律知識基盤 データ登録手順書(v0.6 試作)
## 1. 置き場所
`knowledge/`(法知識・出典資料)、`cases/`(判例)、`indexes/`(再構築可能な検索索引)、`import/incoming/`(取込待ち)、`import/rejected/`(拒否・隔離)。環境変数 `LK_ROOT` で root を切替可能(試験は架空データを別root `lk_test_*` で実施。本番へ混入しない)。
## 2. 取込の順序
出典資料(source) → 段落(passages) → 法知識(knowledge) → 判例(case) → 関連(links)。後続は先行を参照するため。
```
python3 -I scripts/lk_import.py source   import/incoming/sources.json
python3 -I scripts/lk_import.py passages import/incoming/passages.jsonl
python3 -I scripts/lk_import.py knowledge import/incoming/knowledge.json
python3 -I scripts/lk_import.py case     import/incoming/<case_dir>/
python3 -I scripts/lk_import.py links    import/incoming/links.json
python3 -I scripts/lk_index.py rebuild      # 索引の再構築
python3 -I scripts/lk_verify.py store       # 整合性検証(ハッシュ・参照・履歴連鎖)
```
## 3. 検証される項目(不合格は import/rejected へ隔離。既存の正常データは変更されない)
JSON Schema適合/必須項目・型/ID重複/参照先(出典・段落・判例)の存在/原資料パスの安全性(`..`・絶対パス拒否)/SHA-256一致/判決全文と段落テキストの対応/判決全文なしで「全文あり」とする矛盾/存在未確認の判例を原文照合済みとすること/著者の見解を裁判所の判断や法理として登録すること/AI推定のみによる判例変更等の関係登録。
## 4. 入力形式
JSON、JSONL(段落)、UTF-8テキスト、PDF(判決原本)。書誌情報は**分かる範囲のみ**。不明は null とし、`bibliographic_status: unconfirmed`。推測で補わない。
## 5. 判例ディレクトリ
`metadata.json`, `structured.json`, `judgment.pdf` and/or `judgment.txt`, `passages.jsonl`。取込後 `cases/{originals,fulltext,passages,manifests,structured,metadata}` に保存。
## 6. 禁止
書籍・判例・契約書の外部ベクトル化サービスへの送付は利用者の許可なく行わない(本実装は外部送信なし。補助のベクトル検索はローカルTF-IDF)。
