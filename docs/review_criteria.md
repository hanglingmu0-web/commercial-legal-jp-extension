# 共通審査基準(初回レビュー・独立再検証・反証レビューが共通で使う)
**【暫定・要承認】** 当社の確定した審査基準ではない(実務プロファイル未作成)。再現性のために判断の「物差し」をそろえる目的で置く。これを当社基準として扱ってはならない。承認・修正は利用者が行う。共通基準の使用は、初回の結論を再検証担当に開示することとは別である(判断自体は独立させる)。重大なリスクの指摘を抑えるものではなく、画一的な結論を強制するものでもない。

## 1. 入力の固定
- 当社の立場は facts.json の our_role に従う(契約書上の呼称で記載)。立場を取り違えない。
- 判断単位: 契約書の各条を1判断(judgment.clause に「第N条」)。条にまたがる論点・欠落は「契約全体」の判断として別に1件以内で記載してよい(欠落条項の列挙はこの判断内に書く)。
- 事実関係が null/欠落のものは「不明」とし、推測で補わない。不明な事実に依存する判断は『判断保留』または『条件付き』。

## 2. リスク分類(暫定定義)
- A: 法令の適用が確定すれば違反・不利益が直ちに生じ得る条項(適用要件が未確定でも、確定時の影響が大きいもの)
- B: 当社に重大な経済的・供給継続・事業継続上のリスクがある条項(当社の立場で評価)
- C: 当社に中程度のリスクがあり交渉・修正の余地がある条項
- D: 軽微な改善余地(表現・運用上の明確化)
- E: 当社に有利な条項(修正不要。相手方が拒否する可能性は別記)
- F: 問題なし(標準的)
- G: 情報不足により分類できない
※A/Bは高リスク階層の算定に使われる。分類は category_reason に根拠を書く。

## 3. 修正要否の基準(revision_decision)
- 修正要: 当社の立場で、リスク(法的・経済的・履行・紛争)が具体的に特定でき、契約書原文の改訂で軽減できる場合。
- 修正不要: 当社に有利、または標準的で、経済的合理性・当社の立場・リスク配分を評価したうえで問題がない場合。「任意に設定できる」「法令に禁止がない」は理由にならない。
- 判断保留: 必要な事実・一次資料・社内基準が不足し、現時点で判断できない場合(不足するものを具体的に書く)。
- 当社に有利な条項は、修正を提案せず、相手方が拒否する可能性・強制力のリスクのみ注記する。
- 数値は法定率か任意設定かを区別する。法定率は適用が確定し一次資料(機械取得原文)で確認できる場合のみ。

## 4. 法的判断と経済的判断の分離
法的有効性・強行法規適合・適用可否と、経済的合理性・当社立場・リスク配分・履行可能性・紛争時の実効性・交渉・社内基準整合は別評価(term_assessments の各軸)。数値が大きいことだけで違法・無効としない。

## 5. 出力形式
docs/review_schema.md のとおり。計算例は assumed=true。引用は legal_cache の原文からの逐語引用。一次資料(機械取得原文)が無い場合は『確定』を使わない。

## 6. Commercial Legal 本体のレビュー結果がある場合
その指摘(重大度・修正案)を出発点として取り込み、削除する場合は理由を書く(取り込み漏れを防ぐ)。日本法の論点は一次資料確認・適用要件判定で検証する。

## 追補(第5回): 指摘の種別・固定基準なし・法令調査の要否
- 各判断(judgment)と各修正案(revision)に `finding_type` を付ける: law(法令の適用・解釈) / contract_text(契約書原文) / consistency(条項間整合) / economic(経済的合理性) / risk_allocation(契約条件・リスク配分) / internal_standard(社内審査基準) / format(文言・形式) / fact_check(事実確認)。
- **法令を根拠に確定的判断をする場合のみ**、機械取得した一次資料の確認を必須とする。契約書原文・計算・条項間矛盾・定義の欠落・条番号や当事者表記の誤り・負担や履行条件の不明確さ・支払期日や所有権移転時期の不明確さは contract_text/consistency/format として扱い、**法令を取得できなかったことを理由に判断保留にしない**(法令に関する別論点は別の指摘(law)として分けて書く)。
- 損害賠償上限・違約金・保証期間・解約通知期間・知財帰属・管轄等に**固定的な基準は存在しない**。数値を示す場合は『交渉上の提案(選択肢の一つ)』とし、社内基準・必須修正と書かない。複数の合理的選択肢がある場合は、各選択肢の利点・欠点・法的/経済的影響を示す(revisionは選択肢ごとに別案として出してよい。finding_type は economic か risk_allocation)。
- 修正対象文言(original_text)は契約書原文と逐語一致させる(新設条項は位置指定が必要なため、別途『確認事項』として記載)。

## v0.5.0 一般審査原則(第6回の外部検証から抽出。特定契約の正解ではなく、どの契約にも適用する原則)
1. 法的根拠の表示を削除・修正することと、数値の合理性を確認することは別。違約金・遅延損害金・利率等は11項目(設定根拠・想定損害・契約金額・遅延部分と全体・上限・別途賠償・他の違約金との重複・負担・履行可能性・交渉・算定基礎の代替案)で個別に評価し、確認できなければ条項全体を検証済みにしない。
2. 『当社に有利』『当社の取得額が減る』だけを理由に、契約条件を合理的とも不合理とも判断せず、代替案を排除しない。維持する場合は理由を明示する。
3. 数値の計算(累積期間等)の検算は、契約条件の検証の完了ではない。既払分・所有権移転時期・上限・解除・長期遅延時の合理性など関連条項との関係を別に検討する。
4. 他条項を引用・準用する修正は、参照先の実在・内容の適切性・未解消問題・読替えの影響・法令適合性の未確認の無条件な拡張の有無を確認し、問題があれば解消するか条件付きにする。
5. 管轄・有効性・適法性の法的効果は、法令・裁判例・裁判所の公式資料で確認できない限り断定しない(最終結論に限らず全記録で)。
6. 複数条項にまたがる論点は関連条項を明示し、修正後の契約全体で解消したかを確認する。単一条項の修正だけで解決済みとしない。
7. 検証状況は4層(修正文言/法的効果/条項全体/論点全体)で別々に管理し、上位層は下位層を超えない。
8. Wordコメントは件数でなく全文の完全一致で検証する(途切れ・代替案・選定理由の欠落は不合格)。
9. 成果物は社内審査用と相手方提示用を分ける。相手方用には内部判断・交渉許容範囲・AI処理・未採用案を含めない。外部送信は利用者の承認後に人間が行う。
10. 報告は実務用(重大・推奨・確認・残存リスク)と技術検証記録に分け、同じ論点を重複して提示しない。
